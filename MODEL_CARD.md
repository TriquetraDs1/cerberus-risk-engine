# Model Card — Cerberus Point-Risk Baseline

## Intended use

Per-transaction fraud/chargeback risk scoring for a synthetic payment-transaction stream,
as part of a research/demo project. **Not fit for production use as-is** — see
Limitations.

## Model details

- **Type:** Gradient-boosted decision tree (LightGBM; falls back to scikit-learn's
  `HistGradientBoostingClassifier` if LightGBM is unavailable).
- **Inputs:** `amount`, `amount_zscore`, `velocity_count_1h`, `velocity_amount_1h`,
  `hour_of_day`, `is_off_hours`, `day_of_week`, `entity_degree` — see
  `src/cerberus/features/pipeline.py`.
- **Output:** P(fraud) in [0, 1] per transaction.
- **Training split:** time-based (not random) — the model is trained on the first 80%
  of the time window and evaluated on the last 20%, so ring-injected fraud bursts can't
  leak between train and test.

## Training data

100% synthetic, generated by `src/cerberus/data/synthetic_rings.py`:
- Base transactions with an independent per-transaction fraud label (~1.8% base rate),
  amount and time-of-day distributions shifted for fraud rows so the signal is real but
  not adversarially hard.
- Injected coordinated fraud rings (shared device/card, burst timing, structured
  amounts) with ground truth ring membership.
- Innocent household entity-sharing (accounts that legitimately share a device) with
  no fraud label, specifically to let the ring detector's false-positive rate be
  measured honestly.

No real transaction, account, or payment-instrument data is used anywhere in this
project.

## Metrics (see `reports/baseline_metrics.json` for the live numbers)

Reported with the cost basis attached, not as bare accuracy — see
`docs/ARCHITECTURE.md` for why. ROC-AUC and PR-AUC on the held-out time window, plus
total cost (under a placeholder FP/FN cost ratio, see below) at the naive 0.5 threshold
vs. the cost-optimal threshold.

## Known limitations

- **Cost ratio is a placeholder** (`CERBERUS_FP_COST` / `CERBERUS_FN_COST`, default
  5:50), not derived from a real merchant cost study. Treat the reported cost savings
  as directional, not calibrated.
- **Synthetic data only.** No real fraud patterns are guaranteed to resemble the
  synthetic ones; this model has not been validated against a real transaction stream.
- **No adversarial hardening yet** (Day 5-6 in the project plan) — the current baseline
  has not been tested against evasion strategies, so its robustness under an adaptive
  fraud ring is unknown as of this model version.
- **Feature set is intentionally small** (8 features) for a 10-day solo build; a
  production model would need a much richer feature store.

## Retraining

`python scripts/generate_data.py && python scripts/train_baseline.py`. Deterministic
given the same `CERBERUS_RANDOM_SEED`.
