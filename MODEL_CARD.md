# Model Card — Cerberus Point-Risk Baseline

## Intended use

Per-transaction fraud/chargeback risk scoring for a synthetic payment-transaction stream,
as part of a research/demo project. **Not fit for production use as-is** — see
Limitations.

## Model details

- **Type:** Gradient-boosted decision tree (LightGBM; falls back to scikit-learn's
  `HistGradientBoostingClassifier` if LightGBM is unavailable).
- **Inputs (19):** `amount`, `amount_zscore`, `amount_vs_trailing_mean`,
  `velocity_count_{1h,24h,7d}`, `velocity_amount_{1h,24h,7d}`, `hours_since_last_txn`,
  `hour_of_day`, `hour_sin`, `hour_cos`, `is_off_hours`, `day_of_week`, `entity_degree`,
  and a one-hot merchant segment (`segment_grocery_essentials`,
  `segment_electronics_highvalue`, `segment_digital_subscription`,
  `segment_travel_luxury`) — see `src/cerberus/features/pipeline.py`.
  `shared_entity_strength` and `component_size` are computed but **deliberately
  excluded** — see "Identity rotation got worse, and why" below.
- **Hyperparameters:** found by `scripts/tune_baseline.py`, a 40-trial Optuna study
  minimising *cost at the cost-optimal threshold* on the calibration split, not ROC-AUC.
  Checked in as `LGBM_PARAMS`.
- **Output:** a **calibrated** P(fraud) in [0, 1] per transaction — see Calibration
  below. Two model versions exist: `models/point_risk_baseline.txt` (the base model)
  and `models/point_risk_hardened.txt` (retrained on adversarial examples the
  hardening harness found — see Adversarial Robustness below).
- **Training split:** chronological three-way split — train (64%) / calibration (16%)
  / test (20%) — not random, and the calibration split is genuinely disjoint from both
  train and test. See `cerberus.detection.point_risk.three_way_split`.

## Training data

100% synthetic, generated by `src/cerberus/data/synthetic_rings.py`:
- Base transactions with an independent per-transaction fraud label (~1.8% base rate,
  modulated per merchant segment), amount and time-of-day distributions shifted for
  fraud rows so the signal is real but not adversarially hard. The real measured rate in
  Kaggle's `creditcard.csv` is **0.17%** — an order of magnitude rarer. Run
  `scripts/generate_data.py --calibrate-rate` to use it: the model actually scores
  *better* (ROC-AUC 0.858, PR-AUC 0.509), but at a tenth the fraud a 60k-row dataset
  holds ~100 base-fraud rows, so the review tier empties and the segmented decision
  layer's advantage thins to 9.0%. Those are small-sample artefacts; the fix is more
  rows, not a fatter rate. Both configurations reproduce — see
  `docs/EXPERIMENT_ADVANCED_TRAINING.md`.
- Four merchant segments (grocery/electronics/digital/travel) with different amount
  and fraud-rate multipliers, so segment is a genuine risk signal, not just plumbing.
- Injected coordinated fraud rings (shared device/card, burst timing, structured
  amounts) with ground truth ring membership.
- Innocent household entity-sharing (accounts that legitimately share a device) with
  no fraud label, specifically to let the ring detector's false-positive rate be
  measured honestly.

No real transaction, account, or payment-instrument data is used anywhere in this
project.

## Calibration

Isotonic regression fit on the held-out calibration split (`cerberus.detection.
calibration`), not `CalibratedClassifierCV(cv="prefit")` — deprecated in sklearn 1.6,
and a one-line hand-rolled isotonic map is exactly what that method does internally
anyway. `class_weight="balanced"` skews raw LightGBM scores away from true P(fraud);
calibration closes that gap. Last measured: Brier score 0.0819 → 0.0163, expected
calibration error 0.1926 → 0.0023 (see `reports/baseline_metrics.json` for live numbers,
and the System Health page's reliability diagram for a visual).

## Decision layer

Per-segment cost matrices, not one global FP:FN ratio — see `cerberus.decision.
cost_matrix` and `reports/decision_layer.json`. Each segment's cost is derived from its
own mean transaction amount + a documented retention-sensitivity multiplier (a
methodology choice, not a calibrated business study — see Limitations). Segmented
routing costs ~16.5% less than one global threshold applied everywhere.

## Adversarial robustness

The hardening harness (`cerberus.adversarial`, `scripts/run_adversarial_harness.py`)
runs an adaptive local search over three evasion strategies — structuring, identity
rotation, slow-ramp timing — against the live model and ring detector, then retrains
on what it finds. Last measured (`reports/adversarial_hardening_report.json`):

| Strategy | Detection, unattacked | Under attack | After hardening |
|---|---|---|---|
| Structuring | 1.00 | 0.50 | 0.99 |
| Identity rotation | 0.88 | 0.02 | 0.47 |
| Slow ramp | 1.00 | 0.50 | 1.00 |

Structuring and slow-ramp harden well because they're detectable point-risk features
(amount, velocity) that retraining can learn from. **Identity rotation barely
recovers** — it targets the Louvain ring detector specifically, and Louvain is
unsupervised: retraining the point-risk model can't teach a graph community-detection
algorithm anything. This is reported as an open, real limitation, not patched over.

### Identity rotation got worse, and why

An earlier model version held identity rotation at 0.33 under attack. It is now 0.02.
The cause is understood and was found by the harness, not in production: adding graph
features (`component_size`, `shared_entity_strength`) to the *point-risk* model let the
classifier lean on structure that identity rotation exists to dissolve, so its
independent signal collapsed. Those columns were ablated back out of `FEATURE_COLUMNS`,
which recovered most of the loss but not all of it.

The general lesson is worth more than the number: **ROC-AUC was at its highest (0.8206)
in exactly the configuration with the worst adversarial behaviour.** Aggregate metrics
alone would have scored that change as a clean win. Only the adversarial harness caught
it. See `docs/EXPERIMENT_ADVANCED_TRAINING.md` for the three-way ablation.

## Sequence model (secondary signal)

`cerberus.detection.sequence_risk` — a 2-layer GRU over the 8 transactions ending at the
one being scored. Held out: ROC-AUC 0.8371 (above the booster's 0.8153), PR-AUC 0.3011
(below its 0.3141). A 70/30 ensemble reaches PR-AUC 0.3341, beating point-risk alone.

It is weighted 0.3 and is **not** permitted to overrule the booster, because it produces
no reason codes and `docs/ARCHITECTURE.md` §1 requires an explanation on every block. It
is trained and calibrated but not yet wired into the live decision layer.

## GNN ring detector (evaluated, not adopted)

`cerberus.detection.gnn_ring` — GraphSAGE, held-out ROC-AUC 1.0000, 25/25 rings, 1.3%
household false-positive rate against Louvain's 9.3%.

**That perfect score is not evidence the GNN works.** A control that flags every account
with `degree >= 2` matches it exactly — 100% recovery, 1.3% false positives. Message
passing contributed nothing: injected rings are dense cliques (degree 5–11) and innocent
households are single links (degree 1), so one integer comparison separates them. The
number measures how easy the synthetic graph is, which makes it evidence *for* the
"Louvain on synthetic data is easy" critique rather than against it. The control runs on
every invocation and is written into `reports/gnn_ring_metrics.json` so the 1.0000 cannot
be quoted on its own. Louvain remains the default detector.

## Narration layer (A1)

`cerberus.llm` attaches a 2-3 sentence plain-English summary to each decision (in the
dashboard queue and the `GET /explain/{id}` endpoint). It is **not part of the model**:
it reads a decision that has already been made and restates it. The structured
`reason_codes` remain authoritative — the summary is an additional field, and `/explain`
echoes the reason codes so the prose can be checked against them. It runs on Claude when
`ANTHROPIC_API_KEY` is set and on a deterministic template otherwise; it never feeds back
into scoring, calibration, or routing.

## Known limitations

- **Cost matrices are estimates**, not a calibrated business study — derived from mean
  transaction amount + a documented retention-sensitivity multiplier per segment.
- **Synthetic data only.** No real fraud patterns are guaranteed to resemble the
  synthetic ones; this model has not been validated against a real transaction stream.
- **Adversarial validation is scoped to three named strategies**, searched adaptively
  within their parameter ranges. This is not a general adversarial-robustness
  guarantee, and a real fraud ring is not obligated to restrict itself to these three
  moves. The default search is a randomized local hill-climb, not a certified
  worst-case search.
- **The ring detector cannot be hardened the way the point-risk model can** —
  identity rotation's evasion of the graph layer is real and unresolved as of this
  model version.
- **Feature set is intentionally compact** (19 features) for a 10-day solo build; a
  production model would need a much richer feature store.
